# Cross-Index (prototype)

A self-contained browser app for working out a cross-indexing workflow by hand: intake of reports, main files (individuals, groups, subjects, areas), connections tied to their source reports, and a connections chart.

## Run it

Open `index.html` in a browser (double-click it). Nothing to install, no server, no build step. The chart library is included in `vendor/`, so it works offline.

## How it is organised

The menu follows the office: **New report** (the app opens here), **Files**, **Indexes**, **Special banks**, **Investigations**, with Review and Settings off to the side. A search box in the header finds files, items and reports (by number or subject). There is no list of all reports; a file's page holds its reports.

- **Indexes** – the directory room, in two tabs. *Worth a look* (opens first, with a badge counting new discoveries): a row of tiles counts what the indexes show (**Heating up** first: the subjects and areas with more independent reports in the last 14 days than before, or newly connected to other names, each with its fattest related names; the staff member ticks the ones to look into and opens a *special bank* from them, with a reason recorded, and the chart pulls in the heaviest connected names; then new discoveries: a connection entered recently ties files together through a third file, or joins two separate groups, in a way no single report shows; files linked through others; names together with no connection; growing groups; loose ends; possible duplicates). Clicking a tile lists the findings as small pictures with an Open chart button. *Cross-filing*: pick a drawer (individuals, groups, areas, subjects), find a file (type, arrow down, Enter) and open its **connection index**: everything it is connected to, grouped by what is at the other end, with note and source report (also reached from a file's page). The *words staff use for connections* (note wordings with counts, for building a type list later) are an evaluation aid and sit under **Review**. Every lookup box works from the keyboard: arrow down to a match, Enter to pick it. Discoveries use the date a connection was entered; growth uses the source report's date.

- **Reports** – the form follows the paper one: **date of report, subject of report, source of report**. The other fields (where the preserved copy is kept, notes) are optional and always shown; the form is laid out in a tidy grid. Every date field opens a small calendar when clicked (or via the icon) as well as accepting typing (25 Oct. 2026). The sample-data banner is gone; "Start fresh" now lives in Settings, under Data. Kind of source and original text were removed from the form. Saving takes you to the same report's page, which lists **the names mentioned** (pick an existing name as you type, arrow down to a match and press Enter to add; when nothing matches, Enter opens a small dialog with the typed name already filled in, where only the type and optional *identifying details* such as date of birth, address or nickname are left to fill in, so same-named people can be told apart in the match list; the chosen type is remembered for the next name) and **the connections** the report shows (from, plain-language type, to, a required note saying what the connection is; the list starts with just *Connected to*, with a tick box for the full list; the report is the source automatically). A pair can have several connections.
- **Areas** – an *area* is a place in the loose sense: a city, a region, a campus. A single address, plate, phone or account is not recorded as a name; if it matters, put it in the identifying details or a connection note. (Items were removed; older saves that hold them still open.)
- **Entities** – the main files. Name/alias matching helps resolve "same entity or new one?"; entities can be merged (with undo). Heat = independent reports in a recent window.
- **A main file** has tabs that follow the paper file: **Profile** (fields suited to the kind of file: individual, group, area or subject), **Connections**, **Reports**, **Summaries** and **Time line**. A *summary* is written by staff and covers only the reports that are new since the last summary (the tab shows how many are not yet covered); each prints on its own sheet. A *time line* is typed by staff, entry by entry, against the date the event happened, with a level of detail (key event, standard, fine detail) so it can be printed short or long. Several files can be printed as one time line (entries merge in date order, each marked with its file), including all files of a special bank (button on the bank's Files tab). The profile, the connections, a report and an estimate also have Print buttons. All of them print in one common style: document type and file name at the top, date printed and page numbers at the bottom (`documents.js`, `pdf.js`).
- **Special banks** (menu item; formerly Chart) – a special bank is opened when a staff member spots a potential situation in the main files (usually from *Heating up* on Indexes, or started by hand). It is made of main files (references, not copies): the starting subject or area plus its fattest related files, which the staff member ticks in a dialog when opening it, and can add to or remove later. The list page finds, opens, renames, copies and deletes special banks. Each bank has three tabs: **Files** (the list, heaviest first, a lookup box to add any main file, and suggested related files), **Chart** (the connections among its files, with a slim left panel for name types, date range, display toggles and snapshots; the details panel appears only when something is clicked) and **Estimates** (several per bank, so one can be redone or corrected; each stays on record; the estimate page is one form: a summary, "What the files establish" and "Working theories", each statement editable in place, with the reports it rests on chosen from a lookup (reports that name the bank's files first, keyboard works), an established statement needing at least one report, and a button to move a statement between established and theory; everything saves as you go). A bank, with its files, chart and a chosen estimate, is **handed over** to Investigations, which freezes the chart as a snapshot. The arrangement of each chart is saved: toggling options never rearranges it, new files are placed beside the files they connect to, the zoom and pan stay put, and every snapshot keeps its own arrangement (only the Auto-arrange button re-lays-out the chart). Snapshots sit in a collapsible panel; when a comparison is on, a line says what orange means or that nothing is new. A *quick look* from an index finding is not saved and is replaced by the next one; "Open a special bank from this" keeps it.
- **Special bank extras** – a bank can hold **several charts** (selector above the chart; each keeps its own filters, arrangement and snapshots; a new chart starts blank or as a copy; the chart that was handed over cannot be deleted). The chart line also says how many connected files sit outside the bank. A bank shows **what is new since you last looked** (reports and connections on its files; "Mark as seen" clears it; the list shows a badge). 
- **Situation observation** – shows which files moved in the last 7–90 days (more independent reports than the period before, or new links) and which files are active together. It only points; deciding something needs looking into is the staff member's call. "Open a bank" records why the bank was opened.
- **Investigations** – handing a bank over creates one investigation (`V-0001`); **New investigation** opens one without a bank (a tip or referral). Status is Active or Closed. Tabs: Overview (title, reason, investigator, notes, and the name and location of the handling plan, which is written in Word outside the app), Chart, Leads, Requests.
- **Case chart** – the investigators' picture of the major players and how they are related, for one investigation. It looks and prints like the working chart but shows only the main files chosen for it, laid out for the best view. Connections can be drawn by hand (each cites at least one report) or taken from what the main files already record. Free text labels and a title can be added for the wall copy. Open leads put a badge on the files they are about, so the board shows what is next. Anyone can edit it. "Pin to the case chart" / "Add to the case chart" on the working chart send things across for a handed-over bank.
- **Leads and requests** – both belong to an investigation (tabs *Leads* and *Requests* on the investigation page); the collecting side no longer raises them. A **lead** is a question the investigators follow up. It needs only its reason; the report that prompted it, who it is assigned to and the files it is about are optional. Working theories from the handed-over estimate are listed on the Leads tab with *Make it a lead*. A **request** asks Collection to retrieve and preserve something (no interpretation), optionally for a lead. What comes back is filed through Intake as a report carrying the lead or request number. Each investigation prints a **lead list** and a **request list** (all or open only, with a line or two of response), and each lead or request prints as a one-page sheet. A special bank can instead be closed with the finding **no situation** and a reason (Estimates tab); nothing is handed over and it can be reopened.
- **Estimate** (from the chart toolbar) – summary plus statements marked *established* (must cite reports) or *working theory*. "Hand over" freezes a snapshot so later findings show as changes.
- **Pictures** – individuals take a photo and groups a logo (Entity page). They are shrunk in the browser and stored on the entity (`photo`, a data URI), so they travel with the JSON export. Entities without one get a drawn placeholder.
- **Review** – the hesitation log: blocked saves, unclear entity types, flagged matches, created-despite-similar, and your own "Log a snag" notes.
- **Settings** – threat categories (intake basis), source types, connection types and their directions, heat and hub thresholds, data export/import.

### Connection types

Staff pick a plain label that reads as a sentence, *A [label] B* (Knows, Family of, Works for, Member of, Owns, Pays, Lives in, Seen at, Involved in, Connected to and others, grouped as People, Work, Groups, Corporate, Finance, Property and items, Places, Subjects and crime, General). The stored name is the label in UPPER_SNAKE_CASE (`FAMILY_OF`). Any pair of file or item types is allowed; the note says what kind. The list is added once to every data set (older names such as `FUNDED` stay under *Older names* because existing connections use them); staff can add a type on the spot from the report page, and *Settings → Restore the suggested list* adds back any that were deleted.

## Graph schema (Neo4j style)

The data is kept in the shape of a property graph so it can move to Neo4j later without redesign. Names follow Neo4j conventions: PascalCase labels, UPPER_SNAKE_CASE relationship types, camelCase properties.

| Kind | Name | Notes |
|---|---|---|
| Node label | `Individual`, `Group`, `Subject`, `Area` | the four main files; each has `id` (`E-0001`), `name`, `aliases`, `notes` |
| Node label | `Report` | `id` (`R-0001`), `received` (date of report), `subject`, `eventDate`, `sourceType`, `sourceRef`, `basis`, `summary`, `hash`, `dupOf` |
| Node label | `Lead` | `id` (`L-0001`), `bankId`, `kind` (`INVESTIGATION`/`DATA_REQUEST`), `with`, `question`, `raisedBy` (report), `issued`, `status`, `response`; reports point back with `leadId` |
| Node label | `Bank` | a saved view (starting entities, filters, saved positions, `topN`, `estimate`, `handedOver`), not a copy |
| Node label | `Investigation` | `id` (`V-0001`), `bankId` (empty when opened without a bank), `title`, `reason`, `status` (`ACTIVE`/`CLOSED`), `investigator`, `notes`, `planFile` (`name`, `location`), `caseChart` (`title`; `pins` of `entityId`/`x`/`y`; `strings` `C-0001` with `a`, `b`, `label`, `reportIds`; `notes` `W-0001` with `text`/`x`/`y`) |
| Relationship | `(:Report)-[:MENTIONS {role}]->(entity)` | role is one short word: `author`, `named`, `subject`, `payer`, `recipient`, `present` |
| Relationship | `(a)-[:FAMILY_OF {reportId, note}]->(b)` | one relationship per asserting report; never pre-merged; `note` says what the relationship is |
| Relationship types | `MEMBER_OF`, `WORKS_FOR`, `OWNS`, `PAYS`, `LIVES_IN`, `INVOLVED_IN`, … (see Connection types) | directed |
| Relationship types | `KNOWS`, `FAMILY_OF`, `LINKED_WITH`, `CONNECTED_TO`, … | stored with a fixed direction, queried ignoring it |

Files are ranked by *material* reports (the file is part of a recorded connection) rather than mentions, and high-connection files count for half, so a bank can show only its heaviest N files.

Weight is not stored. It is the count of distinct root reports on the relationships between two entities, which in Cypher is `count(DISTINCT rootReportId)`.

## How links and weights work

A link is one report's assertion (from, to, type, source report, optional note). A chart edge groups all links of the same type between the same two entities. **Weight = number of independent reports behind it**; reposts and duplicates count once with the original. Weight is computed, never typed, and there are no source grades or confidence statuses.

## Data

Stored in this browser only (localStorage). Use Settings → Export JSON for backups.
**Do not commit exports to this repository.** Export files contain report data; the repo is for code and the fictional sample data only (`.gitignore` blocks the default export file name).

## Hosting as a Claude artifact

`node build-artifact.js` writes `dist/cross-index-artifact.html`, a single self-contained page (git-ignored) that can be published as an artifact and used inside Claude. Browser pop-ups do not work there, so the app uses its own in-page dialogs and an Export dialog with Copy. PDFs (lead sheets, board, wall chart) are saved through the artifact's download permission, which asks the viewer first.

## Printing the chart for a wall

Chart → *Print for the wall…* splits the chart across tabloid (11 × 17) or letter pages, 1 to 4 across and down, with crop marks and page labels. Print the PDF at 100%, trim at the marks and tape the pages together. The arrangement of tiles is saved per bank (drag them); *Auto-arrange* resets it.

## Tests

`node tests/core.test.js` (logic), `node tests/pdf.test.js` (leads, estimate, ranking, PDFs, tile maths) and `node tests/chart.test.js` (chart elements and styles against the bundled Cytoscape in headless mode). Plain Node, nothing to install.
